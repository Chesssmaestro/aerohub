# Деплой на Render

## Что уже готово

- `render.yaml` — описание сервиса (Blueprint), Render читает его сам.
- `.python-version` — 3.14, как локально.
- `app/db.py` — `connect_args` теперь зависит от драйвера, так что смена БД
  через `AEROHUB_DB_URL` больше не роняет старт.

Новых зависимостей не нужно: `uvicorn` уже в `requirements.txt`, FastAPI —
ASGI, Render запускает его напрямую, без обёрток.

## Шаги

1. **Завести git-репозиторий и залить на GitHub.** Render деплоит только из
   GitHub / GitLab / Bitbucket, папкой загрузить нельзя.

   ```
   git init
   git add .
   git commit -m "AEROHUB portal"
   git remote add origin https://github.com/<логин>/<репозиторий>.git
   git push -u origin main
   ```

2. **Render → New → Blueprint**, выбрать репозиторий. `render.yaml`
   подхватится, менять команды сборки и запуска руками не нужно.

3. **Задать `AEROHUB_STAFF_CODE`** в Environment сервиса. `AEROHUB_SECRET_KEY`
   Render сгенерирует сам и запомнит — трогать его не надо.

4. Первый билд ~2-3 минуты. Адрес будет вида `aerohub.onrender.com`.

## Что нужно знать про бесплатный тариф

**Диск не сохраняется.** Сервис засыпает после 15 минут без трафика, и при
пробуждении контейнер поднимается заново с нуля. Это значит:

- `aerohub.db` создаётся и засеивается заново при каждом старте —
  `init_db()` отрабатывает сам, каталог подтягивается из `data/parts.json`;
- всё, что создано в работе — новые заказы, регистрации, загруженные в
  `media/` файлы — пропадает.

Для показа демо это нормально: портал всегда поднимается в чистом рабочем
состоянии с демо-пользователями. Для реальной эксплуатации — нет.

**Холодный старт ~50 секунд.** Первый заход после простоя выглядит как
зависший сайт.

## Если понадобится сохранность данных

Бесплатный Postgres у Render живёт 30 дней, потом ещё 14 дней грейс-периода —
и удаляется вместе с данными. Как постоянное решение не годится.

Если данные должны жить, вариантов два:

- платный тариф Render (диск + отсутствие сна);
- Oracle Cloud Always Free — обычная виртуалка, проект едет без переделок.

Отдельно: даже с внешним Postgres загрузки из `app/storage.py` останутся на
эфемерном диске. Под них нужен S3-совместимый бакет и правка `storage.py`.
